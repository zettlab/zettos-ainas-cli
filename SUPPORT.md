# Support

**English** · [简体中文](SUPPORT.zh-CN.md) · [Documentation](docs/en/README.md)

The project is preparing its first public Beta. There is no guaranteed response time, enterprise support contract, or long-term maintenance period. Check [compatibility](docs/en/COMPATIBILITY.md) and the notes for the published version before using it in a workflow you depend on.

| Need | Channel |
|---|---|
| Installation problem, bug, or documentation correction | [Public issue forms](https://github.com/zettlab/zettos-ainas-cli/issues/new/choose), English or Simplified Chinese |
| Feature or language request | Feature-request form in the same issue chooser; describe the user task and expected result |
| Vulnerability, credential leak, or unauthorized access | [Private security report](https://github.com/zettlab/zettos-ainas-cli/security/advisories/new) |
| NAS hardware, storage initialization, or firmware administration | Official Zettlab product support; the [Wiki](https://wiki.zettlab.com/) provides product guides |

Before reporting, read [troubleshooting](docs/en/TROUBLESHOOTING.md). Include version, OS/architecture, firmware, reproduction steps, expected behavior, actual behavior, and a redacted error summary. Do not attach a full NAS directory, credential file, or unreviewed diagnostic archive.

A public issue is not a confidential support channel. The maintainers will not need your password in an issue. For a sensitive report, follow [security reporting](docs/en/SECURITY.md).

For regressions, include the last working version and whether rollback helped. Avoid repeated destructive attempts. Rollback restores the CLI and linked skills; it does not undo NAS operations already performed.
